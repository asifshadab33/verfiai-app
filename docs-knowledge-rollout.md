# Knowledge Index and Evidence Library rollout

## Architecture and scope

- `/knowledge` lists editorially approved publisher links, and can query Crossref live for publication metadata. Search results link to DOI originals; they are not hosted or vouched-for research. `/resources` lists reviewed library metadata. `/resources/$slug` shows publisher, original URL, licence/reuse text, verification date, source references and preview; `/account/library-usage` shows actual billing-period usage. Local-only bookmarks never leave the browser.
- `src/lib/library.functions.ts` exposes bounded server queries, issue submissions, and authenticated allowance reads. `src/components/verifai/ResourceBrowse.tsx` handles browsing. `drizzle/migrations/0005`–`0009` create rights, references, issues and quota tables, hide full content from public database SELECT, scope quota to billing environment, and revoke both download-function grants. `src/integrations/supabase/types.ts` is regenerated.
- Rights are default-deny (`PENDING_REVIEW`). Only approved metadata is browsable; `LINK_ONLY` and `RESTRICTED` are never hosted/downloaded. Library downloads are paused: no download endpoint or button is offered, and database EXECUTE is revoked. The dormant quota design requires approved rights, an active Analyst subscription, and a limit of 50 per billing cycle, but is **not available for use**.
- Existing $9/month Pro and its report limits remain unchanged. The user chose **preview-only**; Analyst price, product registration and checkout are **not configured**. No claim is made that any curated resources have passed rights review; the library is empty until reviewed items are added.

## Rollout and operational safeguards

1. Configure existing backend and payment secrets using `.env.example` as a **names-only** template; do not commit actual values. Apply migrations 0005–0009 in numerical order using the project's database migration process. Check column-level grants and that both download functions remain revoked before publishing resources.
2. Curate each index/library entry: confirm publisher, original URL, current rights/permissions, licence and third-party excerpts, region/language, source URLs, original date and `verified_at`. Set `published=true` only after review. Open-licensed and partner material requires recorded permission reference, rights review date, commercial permission, and separately confirmed redistribution/hosting. Verify that takedown/unpublished rows disappear and previously granted download access is blocked.
3. Keep Analyst checkout and downloads disabled under the preview-only decision. Only reconsider in a separate, explicitly approved release with price, billing policy, rights review, product mapping, sandbox renewal/cancellation tests and quota verification; current webhook accepts only Pro.
4. Review security: unauthenticated requests must not read `full_content` or histories; a user must not read another user's issues/downloads; test denied execution of both database download signatures for authenticated users, rights revocation, malformed inputs, and absence of cached private response bodies. Before a separately approved paid launch, test concurrent downloads at 49/50, idempotency, expired/other-environment subscriptions. For high-volume catalogs, add database full-text search and pagination before scaling (current browse returns at most 40 reviewed rows per filter).
5. QA: keyboard/filter/mobile/RTL layout, accurate publisher/licence links and verification timestamps, Crossref outages, empty state, issue reporting, all routes, no regression to report creation or Pro $9 checkout. Verify actual licensed content before announcing availability. Add abuse monitoring and rate limits before opening public issue reporting at scale.
6. Rollback: unpublish catalog items and hide the navigation links first. Download-function EXECUTE is already revoked; keep it revoked. Keep history for audit. Revert migrations only after preserving records and evaluating existing subscriptions; never restore full_content read grants.
